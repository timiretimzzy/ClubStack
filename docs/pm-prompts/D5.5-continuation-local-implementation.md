## Carried decisions (do not re-litigate)

1. **Licensing stays enabled.** Use the generator. Never embed `license.key` in the
   repository and never move or copy it. It stays where the tool produced it.
2. **ClubStack tenders are authoritative.** Preserve cash, card, account and split
   tenders exactly as recorded. The engine receives the single aggregate currency
   line its API supports; the full breakdown is persisted on the fiscal record and
   the mapping is recorded as `aggregate-single-currency`.
3. **ClubStack is authoritative for calculated tax.** Do not re-rate, re-price or
   re-derive tax in the adapter. If the device cannot represent a treatment, stop and
   report it rather than silently adjusting an amount.
4. **Permissions are separate, not one blanket permission.** Device view, device
   manage, day open, day close, transaction view and transaction retry are distinct.
   Device manage, day open, day close and transaction retry are sensitive.
5. **Local implementation and tests are authorised.** Controlled live FDMS
   verification is still required before acceptance, and must be labelled separately.
6. **The second minimal DLL fix is authorised** (timeout handling plus SQLite schema
   ordering), because the original defect blocks every run.

## What to build

- Entity, DbContext configuration and migration for a persisted fiscal document per
  sale and per refund, with the one-invoice-per-sale and one-credit-note-per-refund
  invariants enforced by the database rather than only in code.
- A narrow outbox event written in the same transaction as the sale commit and the
  refund commit.
- A background worker that drives each document to the device exactly once, records
  the engine's receipt verbatim, and defers rather than loses anything on failure.
- A FiscalStackZW adapter that is a singleton, serialises calls, and runs the
  synchronous facade off the request thread.
- A service and API surface for device status, device administration, fiscal day
  control, document search and retry.
- An admin SPA page, plus cashier-visible fiscal state on the POS receipt.
- Permissions, audit records, and tests.
