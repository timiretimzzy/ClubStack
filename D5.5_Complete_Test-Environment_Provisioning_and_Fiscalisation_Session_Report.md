## 4. Root cause of the previous blocker

The earlier attempt failed with:

```
HTTP 404  https://fdmstest.zimra.co.zw/38529/VerifyTaxpayerInformation
```

**FDMS serves two distinct hosts per environment.** The engine composes device routes as
`{ZIMRASERVER}/{deviceId}/{method}`, and `ZIMRASERVER` for TEST is **not** the verification
host. ClubStack's `FiscalEndpoints` was mapping both to `fdmstest.zimra.co.zw`, so every
device route was sent to a host that does not serve them.

## 7. Registration and certificate position `[INSPECTION]`

The earlier "no manifest" blocker was an artefact of using a method that only applies
settings. `RegisterDeviceWithZimra` performs the full lifecycle — taxpayer verification,
CSR creation, device registration, `CertificateUtility.ImportFromServer`, configuration and
server-certificate retrieval — and installs real certificate material. No fabricated
manifest was created and no local certificate is required for a device about to register.

## 8. License ordering `[INSPECTION]`

`SetLicense` is ungated, but `ActivationService` captures the serial when the engine is
constructed. Registration replaces that identity, so the cached instance validates against
the **previous** serial. ClubStack therefore recycles the engine between registration and
license. `InitializeStaticFields` does not reinitialise activation, making the recycle
necessary rather than optional.

## 9. Environment safety guard

The guard deciding whether a call may reach FDMS was rewritten after testing exposed two
real defects in it:

1. **It trusted the engine's `LAST_ENVIRONMENT`.** That value only refreshes along the
   engine's own save path, so after provisioning wrote new hosts it still read
   `production` while the device was on test. The host configuration is now the ground
   truth, because that is what the engine actually uses.
2. **A missing host key was not treated as unsafe.** The engine falls back to a built-in
   value, and that fallback is **production**, so an unset `ZIMRASERVER` on a test device
   would have reached live FDMS. A missing or unrecognised host is now refused.

The guard additionally covers `QRURL` (a customer-facing receipt deep-link), refuses mixed
test/production hosts, honours an operator's `IsTestDevice` declaration regardless of
configuration, and detects identity drift.
